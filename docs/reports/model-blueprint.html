Dhaka Kacchi Model Blueprint

The data comes in by itself. The Mac trains the models every Sunday; after your approval they run on the VPS around the clock. Agents ask the models short questions and get short answers. After every post, the system checks its own prediction and corrects itself.

Mac · Sundays

  1. Pulls the week's data from the VPS.
  2. Full market sweep, data platform, all training and RAG building.
  3. Judges every new model against the current one and writes the justification report.
  4. Uploads candidate packages to the VPS.

VPS · 24/7 (4 cores, 8 GB)

  1. Daily light scrapers and your first-party data.
  2. Telegram + web approval: you approve, then shadow mode, then live; automatic rollback if results drop.
  3. MCP server, model scoring, prediction ledger, monitoring and alerts.
  4. Private link to the Mac over Tailscale; every part in its own Docker container with memory limits.

Automatic rhythm

  1. Every night: new posts, metrics, website visits and orders arrive from the VPS; data checks run.
  2. Every morning (VPS): drafts are scored; the experiment engine updates.
  3. Every Sunday (Mac): all models retrain and are judged; Telegram asks for your approval; a weekly "predicted vs real" report.
  4. Always: if results drop, automatic rollback and an alert to you.

Safety built in

  1. A prediction can't be changed after publishing.
  2. A model is never judged on posts it learned from.
  3. New models run in shadow mode for 2 weeks first.
  4. 10–20% of posts are deliberate experiments, so the system keeps learning instead of repeating itself.

What is needed

Access I need from you

  1. VPS: the host or IP and an SSH user (key login preferred).
  2. A read-only database user on the VPS warehouse. You put it in .env as DK_WAREHOUSE_DSN.
  3. Permission to read orders, order lines, customers (hashed), website events, campaigns, channels, ad spend, social posts and metrics, menu items.
  4. PostHog: confirm website events land in the warehouse table event. If not, a read-only PostHog API key and project ID.
  5. Optional: a YouTube API key, for reading comments.

What you set up (tracking)

  1. A tagged link for every post, creator and community (UTM tags). The variant tag carries the post's prediction ID.
  2. WhatsApp links with a prefilled code, e.g. Hi! [TR-07], so chats can be traced.
  3. Website events firing: social_click, menu_view, add_to_cart, begin_checkout, purchase, contact (WhatsApp tap), each keeping the UTM tags.
  4. "How did you hear about us?" at checkout and in the WhatsApp order flow.
  5. Your content app saves the prediction ID with the platform post ID when it publishes.
  6. Mark paid boosts so they are judged separately.
  7. Marketing consent captured before any reminder message.
  8. High value: a Google Business Profile, so people searching "biryani Berlin" can find you.

  3. The models above, starting with the five that have data ready.
